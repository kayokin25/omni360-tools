# Панель инструментов Omni360 — исходники сборки

Три Python-скрипта перенесены в браузер и вшиты в панель как обычные инструменты
(рядом с калькулятором OmniBuy и картой-компаньоном):

| Карточка в панели | Было | Стало |
|---|---|---|
| Сбор технических требований | `тт/новое/tt.py` | `tools/techreq.html` |
| Сортировка креативов | `подбор крео/match_creatives.py` | `tools/creatives.html` |
| Подбор адресов | `поиск адресов/script.py` | `tools/addresses.html` |

Ничего ставить не нужно: ни Python, ни pandas, ни openpyxl, ни ffmpeg.
Всё считается в браузере, файлы не уходят на сервер.

## Сборка

```bash
python build.py
```

Складывает результат в `dist/` — это же и есть публикуемая папка:

* `dist/index.html` — панель целиком, один файл.
* `dist/tools/*.html` — те же инструменты по отдельности, если нужна прямая ссылка на один.

`build.py` берёт чистую панель из `source/`, добавляет три инструмента в её
`__bundler/manifest` (gzip+base64) и `__bundler/ext_resources`, а в шаблоне заменяет
карточки-заглушки (`note:`) на настоящие `src:` c iframe.

`dist/` намеренно лежит в репозитории: Netlify ничего не собирает, а просто раздаёт
готовую папку. Поэтому **после правок в `lib/` или `tools/` нужно прогнать `python build.py`
и закоммитить `dist/`** — иначе на сайте останется прежняя версия.

## Деплой

Netlify раздаёт `dist/` и поднимает две функции из `netlify/functions/`.
Настройки — в `netlify.toml`, менять в интерфейсе Netlify ничего не нужно, кроме одного:

| Переменная | Значение |
|---|---|
| `GIS_API_KEY` | ключ с dev.2gis.ru |

Задаётся в **Site configuration → Environment variables**. После добавления нужен redeploy.

### Почему ключ 2ГИС не лежит в коде

Репозиторий публичный, поэтому ключа нет ни в нём, ни в исходнике страницы: браузер
обращается к `/api/2gis`, а ключ подставляет функция `netlify/functions/gis.mjs`
из переменной окружения. Пользователь ничего не вводит.

Что это даёт и чего не даёт:

* ключ **нельзя утащить** со страницы и использовать в своих скриптах;
* но сам адрес панели публичный — кто знает URL, тот сможет искать через прокси.
  Проверка `Referer` отсекает встраивание с чужих сайтов, но не прямые запросы.
  Если нужно закрыть доступ целиком — это password protection / access control
  на платном тарифе Netlify.

В `build.py` есть страховка: сборка падает, если в собранные файлы попал ключ
или любой незнакомый uuid.

### Проверить локально, без Netlify CLI

`dev-server.mjs` раздаёт `dist/` и повторяет маршруты `/api/*`:

```bash
GIS_API_KEY=<ключ> node dev-server.mjs
```

Дальше открыть <http://localhost:8971>.

Отдельно проверить сами функции (реальные запросы к 2ГИС и Nominatim):

```bash
GIS_API_KEY=<ключ> node netlify/functions/test_functions.mjs
```

## Что где лежит

```
lib/
  omnilib.js         ZIP (чтение/запись), XLSX (чтение/запись), размеры MP4/MOV, утилиты
  tool-ui.css        общий стиль всех инструментов
  tt-data.js         СГЕНЕРИРОВАН из tt.py — руками не править
  gen_tt_data.py     генератор tt-data.js
  tt-core.js         логика сбора ТТ
  creatives-core.js  логика подбора креативов
  addresses-core.js  логика подбора адресов
tools/
  *.html             страницы инструментов с метками /*__INJECT:файл__*/
netlify/functions/
  gis.mjs            прокси к 2ГИС, подставляет ключ из GIS_API_KEY
  geocode.mjs        прокси к Nominatim (правильный User-Agent + кэш)
  test_functions.mjs проверка обеих функций без деплоя

dist/                результат сборки, его и раздаёт Netlify
build.py             сборка
dev-server.mjs       локальный сервер: dist/ + маршруты /api/*
netlify.toml         publish, функции, редиректы, заголовки
```

### Если в `tt.py` поменялись длительности или алиасы операторов

Словари не дублируются руками — они генерируются из самого `tt.py`:

```bash
python lib/gen_tt_data.py
python build.py
```

`gen_tt_data.py` импортирует `tt.py` и выгружает `INVENTORY_DURATIONS` (269 пар),
`OPERATOR_ALIASES`, правила Russ/MAER/LBL и ссылку на папку Диска в `lib/tt-data.js`.
Путь к `tt.py` — константа `TT` в начале генератора.

## Чем проверялось

Порт сверялся с оригинальными скриптами на реальных данных, а не «на глаз»:

* **ТТ** — `tt.py` и инструмент прогнаны на одной и той же АП
  (`AP_tiest_868095279752977635.xlsx`): 60 строк → 5 после дедупликации, 4 ссылки,
  одна и та же связка без ссылки. Выгруженные xlsx совпадают ячейка в ячейку,
  включая адреса гиперссылок.
* **Креативы** — на настоящем архиве `new 13.07.zip` (1,3 ГБ, 108 видео) и
  `AP_Go_866940235059044833.xlsx`. Совпало всё: 12 связок, 8 закрыто, 4 не хватает,
  5 файлов в архив. Все четыре листа отчёта идентичны `Отчет_подбор_крео.xlsx`,
  а извлечённые видео совпадают по SHA-256 с `Крео_для_загрузки.zip`.
* **Адреса** — живой прогон по 2ГИС и Nominatim из браузера.

Тесты лежат в `lib/test_*.mjs` (node) и `lib/diff_*.py`, `lib/validate_out.py` (сверка
с Python и проверка xlsx через openpyxl):

```bash
node lib/test_lib.mjs
node lib/test_tt.mjs
node lib/test_creatives.mjs
```

## Как собираются адреса

Инструмент делает **два прохода** и объединяет результат: широкий поиск от центра
города (радиус до 40 км) и обход по сетке точек, в каждой точке — полная пагинация.
Дубли снимаются по координатам.

Так сделано не «на всякий случай». В `script.py` сетка появилась из-за двух
ограничений, которые оказались неверными: `page_size` можно до 50 (а не 10),
а число страниц не ограничено вовсе — выдача листается до конца, дальше приходит
404 `itemNotFound`. Казалось бы, сетку можно убрать. Но `point + radius` у 2ГИС —
не геометрический фильтр: для одних запросов `total` растёт с радиусом
(Пятёрочка/Уфа: 72 → 274), а для других скачет и падает (КанАвто/Казань: 7 при 3 км,
3 при 8 км), причём объекты из маленького радиуса в выдачу большого не попадают,
хотя лежат внутри круга.

Замер на четырёх запросах — ни одна стратегия не выигрывает:

| Запрос | Широкий поиск | Сетка 4×4 | Вместе |
|---|---|---|---|
| КанАвто / Казань | 8 | 17 | **17** |
| Пятёрочка / Уфа | 274 | 216 | **275** |
| Магнит / Казань | 315 | 259 | **326** |
| Додо Пицца / Казань | 16 | 75 | **77** |

Поэтому оба прохода нужны. В интерфейсе видно, сколько объектов дал каждый.
Сетку можно выключить (будет быстрее и заметно менее полно).

Проверенные пределы API: `page_size` ≤ 50, `radius` ≤ 40 000 м, страницы не
ограничены, в ответе есть `result.total`.

## Тема оформления

Переключатель светлой/тёмной темы — в шапке панели, выбор запоминается в
`localStorage`. Инструменты получают тему двумя путями: сразу через `#theme=` в
адресе iframe (чтобы не мигало) и через `postMessage` при переключении — тогда
открытый инструмент не перезагружается и не теряет результаты. Цвета вынесены в
CSS-переменные (`lib/tool-ui.css`, `lib/theme.js`).

Важно: **калькулятор надбавки и карта-компаньон остаются тёмными** — они пришли
из исходной панели, своих исходников у нас нет, а их вёрстка написана на
захардкоженных цветах. Чтобы их тоже перекрасить, нужен отдельный набор правок
через `RESOURCE_PATCHES` в `build.py`.

## Заметки по реализации

* **XLSX читается и пишется своим кодом**, без SheetJS — чтобы панель осталась одним
  файлом без внешних зависимостей. Распаковка — штатный `DecompressionStream('deflate-raw')`.
* **Размеры видео берутся из содержимого файла** (боксы `moov→trak→mdia→minf→stbl→stsd`),
  как в `match_creatives.py`, а не из названия. Из больших архивов читаются только
  первый и последний мегабайт каждого видео, поэтому 1,3 ГБ обрабатываются за ~10 секунд
  и память не разрастается. `ffprobe` не нужен.
* **CORS**: Яндекс.Диск отражает заголовок `Origin`, поэтому ТТ тянутся напрямую из
  браузера. 2ГИС и Nominatim идут через функции — не из-за CORS, а чтобы спрятать ключ
  и представиться Nominatim по-человечески.
* Внутри панели инструмент открывается в **blob:-документе**, а относительный `/api/…`
  от blob-адреса не разрешается. Поэтому `addresses-core.js` собирает абсолютный URL
  через `location.origin` (у blob-документа он равен origin создателя). Без этого поиск
  работал бы на отдельной странице и молча падал внутри панели.
* Движок панели (`x-dc`) **не подставляет `{{ }}` внутрь `style-hover`** —
  интерполированные свойства просто выпадают из правила. Поэтому цвета для
  `:hover` заданы CSS-переменными в `<helmet>`, а тему переключает атрибут
  `data-theme` на `<html>`.
* `User-Agent` для Nominatim только на латинице: в значение HTTP-заголовка нельзя
  положить кириллицу — `fetch` падает на преобразовании в ByteString.
* В `build.py` последовательность `</` в JSON-данных экранируется в `<` + `/` —
  иначе парсер HTML закроет `<script>` на первом же `</script>` внутри данных
  и панель не распакуется. В исходном bundle сделано так же. В `build.py` на это есть
  самопроверка, так что молча сломать сборку не получится.
